# ระบบเบิก/คืนเครื่อง v2

PWA แบบ vanilla JS ไม่มี framework — ข้อมูลเก็บบน **Supabase** (Postgres + Auth) และ Deploy บน **Vercel**

## ภาพรวมการทำงาน

| ผู้ใช้ | ทำอะไรได้ |
|---|---|
| **ผู้เบิก** | ส่งคำขอเบิกโดยเลือก **รุ่น + จำนวน** (ขอได้ไม่เกินจำนวน “พร้อมเบิก”) · อ่านประกาศเครื่องเข้าใหม่ · ติดตามสถานะ · ยกเลิกคำขอที่ยังรอจ่าย · เห็น IMEI ของเครื่องที่ได้รับ |
| **ผู้จ่ายเบิก** | สร้าง/แก้ไขรุ่น · **รับเข้าสต็อกด้วยการยิง IMEI** (หรือลง IMEI ให้ของเดิม) · จ่ายตามคำขอโดย **ยิง IMEI ได้เลย ระบบจับรุ่นให้เอง** (สต็อกลดอัตโนมัติ) · รับคืน (สต็อกเพิ่มอัตโนมัติ) · ดูเครื่องค้าง/ประวัติ · พิมพ์เอกสาร · ส่งออก CSV · กำหนดสิทธิ์ผู้ใช้ · เขียนประกาศ (แถบตัวหนังสือวิ่ง + หน้าประกาศ) |

ลำดับ: **ผู้เบิกส่งคำขอ** → **ผู้จ่ายเบิกกด “จ่าย” แล้วสแกน IMEI** → ได้ใบจ่าย → **รับคืนด้วยการสแกน**

เอกสารที่พิมพ์ได้ (A4): ใบขอเบิก · ใบจ่าย (ทั้งใบ / แยกทีละเครื่อง) · ใบรับคืน

## 1) ตั้งค่า Supabase
1. สร้างโปรเจกต์ที่ https://supabase.com
2. **SQL Editor** → วางไฟล์ `supabase/schema.sql` ทั้งไฟล์ → **Run**
   - รันซ้ำได้ ไม่ลบข้อมูลเดิม และใช้ **อัปเกรดจากเวอร์ชันแรก** ได้เลย
3. (แนะนำ) **Authentication → Sign In / Providers → Email → Allow new users to sign up = ปิด**
   — แอปสร้างบัญชีผ่านฟังก์ชันในฐานข้อมูลเอง ไม่ใช้ระบบสมัครของ Supabase จึงปิดได้ (ปลอดภัยกว่า) และไม่ต้องสนค่า Confirm email
4. **Project Settings → API** คัดลอก `Project URL` และ `anon public` key

### บัญชีผู้ใช้ / สิทธิ์
- เข้าระบบด้วย **ID + รหัสผ่าน** (ไม่ต้องมีอีเมล) — บัญชีอีเมลเดิมยังเข้าได้โดยพิมพ์อีเมลเต็มในช่อง ID
- ผู้ใช้ **สมัครเองได้** ที่หน้าเข้าสู่ระบบ → เป็น “ผู้เบิก” · ผู้จ่ายเบิกเพิ่มผู้ใช้/เปลี่ยนสิทธิ์ได้ที่ ⚙️ ตั้งค่า
- เปิด/ปิดการสมัครเอง: ⚙️ ตั้งค่า → ติ๊ก “ให้ผู้ใช้กดสมัครใช้งานเองได้” (หรือ Environment Variable `ALLOW_SIGNUP=0` เพื่อซ่อนถาวร)
- ลืมรหัสผ่าน: ผู้จ่ายเบิกกด 🔑 ที่ชื่อผู้ใช้ใน ⚙️ ตั้งค่า เพื่อตั้งรหัสใหม่ · ทุกคนเปลี่ยนรหัสตัวเองได้ในหน้าตั้งค่า
- ผู้ใช้ **คนแรก** ของระบบ = ผู้จ่ายเบิก · ตอนอัปเกรดจากเวอร์ชันแรก ผู้ใช้ที่มีอยู่แล้วทุกคน = ผู้จ่ายเบิก
- ใน Supabase → Authentication → Users บัญชี ID จะแสดงเป็น `ID@loan.local` (ไม่มีการส่งอีเมลใด ๆ)

## 2) Deploy บน Vercel
1. push โฟลเดอร์นี้ขึ้น GitHub แล้ว **Add New → Project** เลือก repo (Framework Preset: *Other*)
   — `vercel.json` ตั้ง build command และ output directory (`public`) ไว้แล้ว
2. **Settings → Environment Variables** เพิ่ม
   - `SUPABASE_URL` = Project URL
   - `SUPABASE_ANON_KEY` = anon public key
   - `ORG_NAME` = ชื่อบริษัท/สาขาบนหัวกระดาษ (ไม่บังคับ)
   - `ALLOW_SIGNUP` = `0` ถ้าไม่ให้ผู้ใช้สมัครเอง (ไม่บังคับ ค่าเริ่มต้นคือสมัครได้)
   (ถ้าใช้ Supabase Integration ของ Vercel ชื่อ `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` ก็ใช้ได้เลย)
3. Deploy — `build.js` จะสร้าง `public/config.js` จากค่าเหล่านี้ (ถ้าไม่ตั้งค่า build จะล้มพร้อมข้อความบอก)

หรือใช้ CLI: `npm i -g vercel && vercel --prod`

> anon key เป็นคีย์สาธารณะโดยออกแบบ ความปลอดภัยอยู่ที่ RLS: ต้องล็อกอินจึงอ่านได้ (ผู้เบิกเห็นเฉพาะคำขอของตัวเอง)
> และเขียนได้ผ่านฟังก์ชันใน `schema.sql` เท่านั้น ซึ่งตรวจสิทธิ์ผู้จ่ายเบิกทุกครั้ง **ห้ามใส่ `service_role` key ในแอปเด็ดขาด**

## รันในเครื่อง
แก้ `public/config.js` ใส่ URL/key แล้ว `npx serve public` (กล้องใช้ได้บน `localhost` หรือ HTTPS เท่านั้น)

## โครงสร้าง
```
public/              ไฟล์เว็บ (index.html, app.js, style.css, sw.js, manifest, icons, config.js)
supabase/schema.sql  ตาราง + ฟังก์ชัน + RLS (ติดตั้งใหม่ หรืออัปเกรดจาก v1)
build.js             สร้าง config.js จาก env ตอน build
vercel.json          build/headers
```

## Activate (v2.7)
- เมนู **Activate** (ทั้งผู้เบิกและผู้จ่ายเบิก): ยิง/กรอก IMEI → ระบบเติมรุ่นให้ถ้า IMEI อยู่ในสต็อก → ใส่สี → บันทึก = **Activated** ทันที
- ติ๊ก “ยิงแล้วบันทึกทันที” เพื่อ Activate หลายเครื่องสีเดียวกันต่อเนื่อง (ยิงอย่างเดียว)
- IMEI เดียว Activate ได้ครั้งเดียว · รายการสถานะค้นหาได้ ส่งออก Excel ได้ · ลบได้โดยผู้จ่ายเบิกหรือคนที่บันทึกเอง

## สต็อกแบบ IMEI (v2.5)
- **รับเข้าใหม่**: สต็อก → 📥 รับเข้า IMEI → เลือกรุ่น → ยิง IMEI → บันทึก (สต็อกเพิ่มตามจำนวนที่ยิง)
- **ลง IMEI ของเดิม**: ของที่มีอยู่แล้วแต่ยังไม่มี IMEI → เลือกโหมด “ลง IMEI ของเดิม” → ยิง (สต็อกไม่เปลี่ยน)
- **จ่าย**: ยิงเครื่องไหนก็ได้ ระบบดูจาก IMEI ว่าเป็นรุ่นอะไร · ยิงผิดรุ่น/เกินจำนวน/ไม่อยู่ในคลัง → ไม่รับ (ตรวจทั้งในแอปและฐานข้อมูล)
  เครื่องเดิมที่ยังไม่ลง IMEI ยังจ่ายได้ (แตะเลือกรุ่นก่อนยิง) จนกว่าจะลงครบ
- **ตัดออก**: 📋 IMEI → ตัดออก (ต้องใส่เหตุผล) · ปุ่ม “± จำนวน” ใช้กับของเดิมที่ยังไม่ลง IMEI เท่านั้น
- **พร้อมเบิก** = คงเหลือ − จำนวนที่คำขออื่นจองไว้ (รอจ่าย) · ผู้เบิกขอเกินจำนวนนี้ไม่ได้
- **นำเข้า/ส่งออก Excel** (สต็อก → 📄 Excel):
  1. เลือกรุ่น + จำนวน (เพิ่มรุ่นใหม่ได้) → ดาวน์โหลดตาราง `.xlsx` ที่ใส่รุ่นไว้ให้แล้ว
  2. กรอก/ยิง IMEI ลงคอลัมน์สีเหลือง (ตั้งเป็นข้อความไว้แล้ว ไม่กลายเป็น 3.57E+14) · ใช้ได้ทั้ง Excel / Google Sheets
  3. นำเข้าไฟล์ (.xlsx หรือ .csv) → ตรวจตัวอย่าง (แถวที่มีปัญหาจะถูกข้ามและบอกเหตุผล) → กดนำเข้า → กลับหน้าสต็อกอัตโนมัติ

## หมายเหตุการทำงาน
- จ่าย/คืนเป็น transaction เดียวทั้งใบ และมี unique index กันจ่ายเครื่อง IMEI เดียวกันซ้อน แม้ 2 คนสแกนพร้อมกัน
- รับคืน: แตะการ์ดชื่อผู้เบิก (หรือยิง IMEI เลย ระบบเลือกผู้เบิกให้) → เห็น IMEI ทั้งหมดของคนนั้น → ยิงอย่างเดียว ระบบจับคู่ให้เอง
  เครื่องที่ไม่ได้ยิง: กด “ขาย” = ปิดรายการโดยไม่คืนเข้าสต็อก (ไม่ต้องยิงเลข) · ที่เหลือค้างต่อ ต้องใส่เหตุผล
  ทั้งหมดบันทึกไว้ในใบรับคืน และเหตุผลแสดงที่เครื่องที่ยังค้าง
- หน้าพิมพ์: ไม่เกิน 12 แถวใช้ตารางใหญ่ (มีช่องสภาพ/หมายเหตุ) · มากกว่านั้นจัดกลุ่มตามรุ่น IMEI 4 คอลัมน์ ~70–100 เครื่องจบใน A4 ใบเดียว
- ⚙️ ตั้งค่า → ล้างข้อมูล: ล้างในเครื่อง (แก้แอปค้าง/ไม่อัปเดต) · ผู้จ่ายเบิกล้างประวัติในระบบ หรือล้างทั้งหมดรวมรุ่น (ต้องพิมพ์ยืนยัน)
- จ่ายไม่ครบตามที่ขอได้ (ระบบถามยืนยัน) — คำขอจะปิดเป็น “จ่ายแล้ว” พร้อมบันทึกจำนวนจ่ายจริง
- ตอนจ่าย สต็อกในระบบติดลบได้ (เครื่องอยู่ในมือแล้ว) แต่แอปจะเตือนและแสดงเป็นสีแดง → ใช้ “ตรวจนับ” ปรับยอดให้ตรง
- ตอนสร้างรุ่นใหม่ เครื่องที่ค้างจากเวอร์ชันแรกที่ชื่อรุ่นตรงกันจะถูกผูกกับรุ่นนั้น เมื่อคืนสต็อกจะเพิ่มให้
- เลขที่เอกสาร `REQ-YYMMDD-001` / `ISS-YYMMDD-001` / `RET-YYMMDD-001` ตามวันเวลาไทย
- ต้องออนไลน์จึงบันทึกได้ (service worker แคชเฉพาะตัวแอป) ร่างที่ยังไม่ยืนยันจะถูกเก็บในเครื่อง


## v2.8 — Activate: ลงย้อนหลัง / สิทธิ์การดู / ลิงก์แชร์
- **ลงข้อมูลย้อนหลัง**: ช่อง “วันเวลา Activate” ในฟอร์ม (เว้นว่าง = ตอนนี้) · กด ✎ ที่แต่ละแถวเพื่อแก้วันที่ / รุ่น / สี / หมายเหตุ หรือลบ
- **สิทธิ์การดู** (ผู้จ่ายเบิกตั้งในหน้า Activate → 🔒): ทุกคนเห็นทั้งหมด · ผู้เบิกเห็นเฉพาะของตัวเอง · เฉพาะผู้จ่ายเบิก (ผู้เบิกจะไม่เห็นเมนูนี้)
- **ลิงก์ลับดูตาราง (ไม่ต้องล็อกอิน)**: เปิดสวิตช์ → คัดลอกลิงก์ `https://<เว็บ>/?share=...` ส่งให้ใครก็ได้ ดูอย่างเดียว ไม่แสดงชื่อผู้บันทึก รีเฟรชเองทุก 1 นาที · ปิดสวิตช์ = ลิงก์ใช้ไม่ได้ · “สร้างลิงก์ใหม่” = ลิงก์เก่าใช้ไม่ได้ทันที
- อัปเดต: รัน `supabase/schema.sql` ใหม่ 1 ครั้ง แล้วอัปโหลดไฟล์ขึ้น GitHub

## v2.9 — ลบ / แก้ไขข้อมูลที่ลงไว้แล้ว
- **Activate**: ทุกแถวมี ✎ แก้ไข และ ✕ ลบ · กด “☑ เลือกหลายรายการเพื่อลบ” → ติ๊กหลายแถว (หรือ “เลือกทั้งหมด” ตามที่ค้นหา/กรองอยู่) → 🗑 ลบทีเดียว · ผู้เบิกลบได้เฉพาะที่ตัวเองบันทึก
- **IMEI ในสต็อก** (หน้าสต็อก → 📋 IMEI ของรุ่น):
  - ✎ แก้เลข IMEI ที่ยิงผิด / ย้ายไปรุ่นอื่น (จำนวนสต็อกย้ายตามอัตโนมัติ)

  - 📤 ตัดออก (เสีย/หาย) ยังอยู่เหมือนเดิม (เก็บประวัติไว้)
- อัปเดต: รัน `supabase/schema.sql` ใหม่ 1 ครั้ง แล้วอัปโหลดไฟล์ขึ้น GitHub

## v3.0 — หมวดของใช้ / อุปกรณ์ (เก้าอี้ บูธ โต๊ะ ...)
- หน้า **สต็อก** มี 2 แท็บ: 📱 เครื่อง (IMEI) · 🪑 ของใช้ / อุปกรณ์
- ของใช้นับเป็นจำนวน ไม่มี IMEI · ตั้งหน่วยได้ (ตัว / ชุด / ใบ ...) · รับเข้า/ตัดออก/ตรวจนับ ด้วยปุ่ม “± รับเข้า / ตัดออก”
- ตั้งได้ทีละรายการ: **↩ ต้องคืน** (เก้าอี้ บูธ — ขึ้นในหน้าค้างอยู่ และรับคืนเป็นจำนวน) หรือ **✓ ใช้แล้วหมด** (ถุง สติกเกอร์ — เบิกแล้วตัดสต็อกเลย)
- ผู้เบิกขอของใช้ได้ในหน้าคำขอเดียวกับเครื่อง (ไม่เกินจำนวนพร้อมเบิก)
- จ่าย: ของใช้ไม่ต้องยิง ใส่จำนวนที่จ่ายจริง (ตั้งไว้ตามคำขอให้แล้ว)
- รับคืน: ใส่จำนวนที่คืน คืนบางส่วนได้ · ที่ไม่ครบ เลือก “ไม่คืนแล้ว” (เสีย/หาย/ใช้หมด) หรือให้ค้างต่อพร้อมเหตุผล

## v3.1 — บัญชี “ผู้ดู Activate”
- สิทธิ์ใหม่ (นอกจาก ผู้เบิก / ผู้จ่ายเบิก): ล็อกอินแล้วเห็น **เฉพาะเมนู Activate** ดูได้อย่างเดียว — บันทึก แก้ ลบ ขอเบิก ไม่ได้ และไม่เห็นคำขอ/การยืมของใคร
- เห็นตาราง Activate ทั้งหมดเสมอ แม้ตั้งสิทธิ์ Activate เป็น “เฉพาะผู้จ่ายเบิก”
- สร้างได้ที่ ⚙️ ตั้งค่า → เพิ่มผู้ใช้ → สิทธิ์ “ผู้ดู Activate” หรือเปลี่ยนสิทธิ์ผู้ใช้เดิมในรายชื่อผู้ใช้ (สมัครเองเป็นสิทธิ์นี้ไม่ได้)
- อัปเดต: รัน `supabase/schema.sql` ใหม่ 1 ครั้ง แล้วอัปโหลดไฟล์ขึ้น GitHub

## v3.2 — หน้า “ค้างอยู่”: วันที่ + พิมพ์
- แต่ละคนแสดงรายการแยกตาม รุ่น + วันที่เบิก (📅 วันที่ · ค้างกี่วัน — เกิน 7 วันเป็นสีแดง) · หน้ารายละเอียดมีคอลัมน์วันที่เบิก
- 🖨️ พิมพ์ที่การ์ดแต่ละคน / ในหน้ารายละเอียด = ใบ “รายการค้างคืน” ของคนนั้น (IMEI · รุ่น · วันที่เบิก · ค้างกี่วัน · ใบจ่าย · หมายเหตุ + ช่องเซ็น)
- 🖨️ พิมพ์ทั้งหมด (บนสุดของหน้า) = “รายงานรายการค้างคืน” ทุกคนในใบเดียว (ถ้าค้นหาอยู่จะพิมพ์เฉพาะที่ค้นหา)
- อัปเดต: อัปโหลดไฟล์ใน 2-GitHub ขึ้น GitHub (ไม่ต้องรัน SQL)
